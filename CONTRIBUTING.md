# Contributing

Thanks for helping improve Me-as-a-Service.

## Development workflow

1. Create a focused branch from `main`.
2. Keep personal content separate from reusable application code.
3. Add or update tests for behavior changes.
4. Run `pnpm check` before opening a pull request.
5. Document architectural decisions that introduce a provider or major dependency.

Do not commit secrets, private career information, production conversations, or
copyrighted source material that cannot be redistributed. Anything under
`private` should not be committed.

## Commit style

Use short, imperative commit subjects. Conventional Commit prefixes such as
`feat:`, `fix:`, `docs:`, and `chore:` are encouraged but not required.
